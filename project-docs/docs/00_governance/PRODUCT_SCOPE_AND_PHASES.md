# Product Scope and Phase Boundaries

> **Kadmeion planning artifact · 12 November 2026 · NOT IMPLEMENTED.** `[APPROVED]` = explicit owner choice; `[PROPOSED]` = specification or architecture suggestion; `[PROOF]` = requires technical/test evidence. No code, deployment, integration, screenshots or performance claims are implied.

**Approved Phase 1:** email/password and optional Google Auth, account recovery, private developer identity and public profile activation, manual/link-based projects and modular case studies, reusable portfolio templates and Blank, three-pane capable-device builder, protected custom code, responsive visitor previews, staging, preflight, immutable static releases, rollback/unpublish, portable project/static export, 15-day item Trash, security/privacy settings, restricted Users and Moderation/Appeals. Required security/event logging accompanies privileged action.

**Approved Phase 2:** Personal Growth hub, separate private DevScore and goals, permitted handle-based public platform fact retrieval and manual Sync, optional unified activity view, opted-in aggregate portfolio visitor analytics and accurate dashboards.

**Approved Phase 3:** Optional sanitized AI assistance after explicit consent and free API safety/availability checks; advanced administrator activity/analytics reporting. An eventual hosted contact form is conditional beyond default external-link contact actions; it is not committed to P1.

**Excluded from v1 core unless separately approved:** anonymous portfolio authoring, mobile phone portfolio/code editing, mandatory GitHub OAuth/repo import, public leaderboards, unrestricted public custom JavaScript, untrusted npm/server code, arbitrary external site reverse-engineering, real-time multi-editor collaboration, public component marketplace, CLI.

**Student/project boundaries:** Strict ₹0 recurring services; free/open-source code dependencies; new Kadmeion repository; older DevFolio code reference only. Offline demonstration and portable export are risk controls; public hosting persistence cannot be guaranteed if a third-party free provider disappears.

### Phase gating

No phase counts as delivered from documentation alone. P1 requires auth/RLS/email/public-revocation proof; P2 requires consent/tracking/source-permission proof; P3 requires opt-in/privacy/sandbox and cost proof. See [`DELIVERY_PLAN.md`](../06_capstone/DELIVERY_PLAN.md).

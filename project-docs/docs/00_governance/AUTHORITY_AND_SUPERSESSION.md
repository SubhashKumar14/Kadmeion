## Labels and authority

| Label | Meaning | Allowed use |
|---|---|---|
| `[APPROVED]` | Latest explicit owner decision; ID traceable to UI-001…115 or older decisions not superseded | Write acceptance requirements; do not infer successful implementation |
| `[DERIVED]` | Engineering consequence of approved behavior | Make proposal with risk/trade-off; do not mark owner-selected |
| `[PROPOSED]` | Default design, route name, data field or tool choice requiring ordinary implementation review | Verify against architecture and owner constraints |
| `[PROOF]` | Hosting, provider, browser, security, legal or cost assertion not locally demonstrated | Block or defer if safety/security-critical |
| `[DEFERRED]` | Phase 2 or Phase 3; not deleted from product | Design without pretending P1 ships it |
| `NOT_IMPLEMENTED` / `NOT_RUN` | No feature code, integration, provider, browser or acceptance tests performed in this documentation task | Preserve until actual evidence exists |

# How to run this kit

The recommended structure is sixteen chats named Session 0 through Session 15. Existing Sessions 0–6 continue; add Sessions 7–15. Keep the same Notion coordination tree. This kit does not start background sessions or merge code.

1. Open **Session 0**. Attach this complete ZIP (or its extracted files), paste MASTER_PROMPT.md, then prompts/SESSION_00.md. Tell it to activate B16 after checkpointing existing workers and establishing the ownership transfers. S0 publishes the exact plan/ownership/log links in Notion and docs; it does not replace historical records.
2. Open **Session 15** with the same master and SESSION_15.md. S0 and S15 record the integration lease transfer. S15 becomes the sole integration/main custodian; S0 remains coordinator.
3. Send existing **S1–S6** their corresponding prompt plus the master. Ask them to preserve current branches/PRs, checkpoint and release only the named transferred paths. Do not reset them or recreate their implemented features.
4. Start **S7–S14** with the master and their individual prompt. They can read/plan independent work immediately, but cannot edit transferred files until RELEASED→S0 GRANT→ACK and B16_ACTIVE are recorded.
5. All sessions use https://app.notion.com/p/41ab082297c78134b007f69c52bd5475 and the linked B16 page https://app.notion.com/p/41bb082297c781948335e8728d512fa9. S0 creates new worker logs under that existing tree. An individual chat's rename does not create ownership or connect it automatically.
6. Resume yielded sessions explicitly. Use the recovery/resume prompt in COORDINATION_PROTOCOL.md. Ask S0 to process progress in batches and S15 to integrate ready exact dependencies; you do not need to copy every report if Notion reads work.
7. At H16 ask S0 for the remaining critical path and whether full scope is still achievable. At H20 S15 freezes feature admissions and validates the final tree. At H24 obtain actual status, not a forced complete claim.
8. Approve only the concrete final main PR/commit and separately any needed hosted actions when ready. S15 verifies the resulting main tree and retained work after any authorized merge. No broad 'merge all branches' instruction.

## What to paste now into Session 0

```text
Activate the Kadmeion B16-v1 plan from the attached execution kit and its linked Notion page. First verify latest live refs/logs and checkpoint S1–S6. Preserve all existing work. Establish the file leases and transfer sole integration/main custodianship to S15 before new workers edit. Keep the same Notion coordination tree. Start the 24-hour clock only when you publish B16_ACTIVE with exact base, branch/log map and ownership ACKs. Target all approved P1/P2 requirements; do not weaken acceptance or silently drop scope. Route concrete file-budget/provider decisions early while independent implementation continues. Do not merge main or activate production under an unspecified future approval.
```

## Kit contents

- MASTER_PROMPT.md: shared rules for all sixteen sessions.
- prompts/SESSION_00.md … SESSION_15.md: sixteen concrete assignments with exact owned path inventories.
- EXECUTION_PLAN.md: 24-hour waves, bottlenecks, completion criteria and premortem.
- LATEST_STATE.md / .json: live reviewed PR/branch/CI checkpoint and changes since the audit.
- FILE_OWNERSHIP.csv: all 431 known paths, old/new writers and transfer gates.
- WORKFLOW_BACKLOG.csv: all 53 workflows and current remaining work.
- REQUIREMENT_LEDGER.csv: all 468 registered IDs; historical evidence preserved, mappings requiring review explicitly marked.
- CONTRACT_QUEUE.csv: 14 producer/consumer contract handoffs.
- RELEASE_MANIFEST.csv / INTEGRATION_QUEUE.csv: seed provenance and merge batches for S15.
- DOCUMENT_REFERENCE_INDEX.md: all 165 tracked project-docs paths, existing log and approval links.
- COORDINATION_PROTOCOL.md / MERGE_AND_RELEASE_RUNBOOK.md: communication, recovery and safe final main assembly.
- AUDIT_REPORT.html: prior detailed audit; LATEST_STATE supersedes its older worker checkpoints.
- validation.json / CHECKSUMS.sha256: structural completeness and artifact integrity, not application test passes.

Source status, isolated test status, hosted status and manual approval remain different fields. The kit does not claim every required behavior fits in one day; it gives every omission an owner and an explicit gate.

You can also open the sixteen linked assignments directly from the Notion B16 page; NOTION_ASSIGNMENTS.md provides every exact URL. NEW_FILE_RESERVATIONS.csv and NEW_FILE_POLICY.md make the proposed 15-file envelope concrete; it remains unapproved until the owner decision is recorded.
